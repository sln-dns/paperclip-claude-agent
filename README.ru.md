# paperclip-claude-agent

Подключение **живой сессии Claude Code** к [Paperclip](https://github.com/paperclipai/paperclip)
внешним агентом. Задачи, назначенные агенту в Paperclip, приходят в вашу работающую сессию;
сессия отвечает в тикете, закрывает задачи и ставит задачи другим агентам.

## Зачем

Родные адаптеры Paperclip на каждое пробуждение **сами запускают** рантайм агента
(`claude`, `codex` и т. д.) на хосте Paperclip или в песочнице, с учётками, которые хранит
Paperclip. Это не подходит, когда у каждого уже есть свой агент — долгоживущая сессия Claude
Code со своим контекстом, данными и подпиской, — а нужна общая доска.

Официальный `@paperclipai/mcp-server` даёт такой сессии **читать** доску, но не работать на ней:

- записи агента (взять задачу, комментарий, статус) Paperclip принимает **только внутри
  активного запуска** (`X-Paperclip-Run-Id`), а у живой сессии его нет;
- при назначении задачи живую сессию никто не будит.

Набор закрывает оба пробела маленькими скриптами, без правок Paperclip и без ключей
провайдеров на хосте Paperclip.

## Как это работает

1. Задачу назначают агенту → Paperclip начинает запуск и выполняет команду агента —
   **держатель** `pc-handoff`. Он кладёт номер запуска в очередь агента и держит запуск
   открытым, пока задача в работе.
2. **Разрешатель** `pc-handoff-resolve` (root, cron на хосте Paperclip) находит в базе,
   к какой задаче относится запуск.
3. **Сторож** `paperclip-watch` на машине агента читает свою очередь через пользователя
   `pcqueue` (одна разрешённая команда, только своя очередь) и печатает одну строку в
   tmux-окно сессии — только если строка ввода пуста.
4. Сессия **читает** через MCP, **пишет** через `pc`: он подставляет номер запуска.

Подробно: [docs/architecture.md](docs/architecture.md).

## Агенту (пользователю Claude Code)

Нужно: Claude Code **внутри tmux**, `python3`, `ssh`, Node 18+ (`npx`).

```
/plugin marketplace add sln-dns/paperclip-claude-agent
/plugin install paperclip@paperclip-claude-agent
```

Затем вставьте приглашение агента из Paperclip:

```
/paperclip:join <текст приглашения или ссылка>
```

Скилл подаст заявку, дождётся одобрения, сохранит ключ агента в `~/.config/paperclip/.env`
(права 600), поставит `pc` и `paperclip-watch` в `~/.local/bin` и выведет строку для
оператора Paperclip. Когда оператор её выполнит:

```
paperclip-watch --check
paperclip-watch --install-cron
```

Перезапустите Claude Code в проекте. Задачи приходят строкой
`[Paperclip] Task for <agent>: PRO-7 ...`, как отвечать — описано в скилле `paperclip:tasks`.
Диагностика — `/paperclip:status`.

## Оператору Paperclip

Один раз на хост: [docs/operator.md](docs/operator.md) —
`sudo server/install.sh --service-user <пользователь Paperclip> --database-url <postgres url>`.

На каждого агента: одобрить заявку в интерфейсе, затем
`sudo server/add-agent.sh <agentId> '<публичный ключ очереди>'` (агент выводит его сам).

## Безопасность

- Ключ агента остаётся на машине агента; хост Paperclip ключей провайдеров не видит.
- У `pcqueue` одна принудительная команда на ключ, каждый видит только свою очередь:
  без оболочки, без проброса портов.
- Базу Paperclip читает только разрешатель под root.
- Текст задач от других людей и агентов — запрос, а не команда (скилл `paperclip:tasks`).
